1. Caméras événementielles

Une caméra événementielle (Dynamic Vision Sensor, DVS) ne capture pas des images à intervalle régulier. Chaque pixel déclenche de façon asynchrone un événement dès que la variation de luminosité dépasse un seuil logarithmique.

Caméra frame classique

  • Captures synchronisées (ex. 30 fps)
  • Toute la scène en même temps
  • Motion blur à haute vitesse
  • Latence ~33 ms

Caméra événementielle (DVS)

  • Événements asynchrones (~µs)
  • Seuls les changements sont enregistrés
  • Pas de motion blur
  • Latence ~1 µs, très faible consommation

Chaque événement est un tuple (t, x, y, p) :

ChampTypeDescription
tfloat (s)Timestamp microseconde
x, yuint16Coordonnée pixel (0..W-1, 0..H-1)
pboolPolarité : 1 = luminosité ↑ / 0 = luminosité ↓
Flux brut d'événements — chaque point est un événement individuel déclenché par un pixel

Le modèle lit les événements depuis des fichiers .npz via ms_model/io/loaders.py et les stocke dans un EventArray (classe dataclass définie dans ms_model/io/events.py).

3. Représentation Voxel Grid

Utilisée par le pipeline ConvLSTM. Le flux d'événements dans une fenêtre temporelle est encodé en un tenseur 3D : (nb_bins, H, W).

Principe

Le temps est divisé en nb_bins intervalles égaux. Chaque événement est distribué par interpolation bilinéaire trilinéaire sur les voxels voisins (interpolation spatiale + temporelle), pondéré par sa polarité (±1).

Conversion d'une fenêtre d'événements en Voxel Grid (5 bins temporels). Valeurs positives = polarité +1, négatives = polarité −1, interpolées.
# ms_model/representations/voxel.py
def to_voxel_grid(xs, ys, ts, ps, H, W, nb_of_time_bins=5):
    # Normalise le temps → [0, nb_bins-1]
    t = (ts - ts[0]) * (nb_of_time_bins - 1) / (ts[-1] - ts[0])
    # Interpolation trilinéaire (8 voisins : left/right × x × y × t)
    weight = polarity * (1 - |lim_x - x|) * (1 - |lim_y - y|) * (1 - |lim_t - t|)
    voxel_grid.index_add_(...)
    return voxel_grid  # (nb_bins, H, W) float32

4. Représentation Event Slice (3 canaux)

Utilisée par le pipeline EV-IMO. Une fenêtre temporelle fixe de 25 ms est convertie en un tenseur (3, H, W) :

Canal 0 — Comptage positif

Nombre d'événements p=1 par pixel dans la fenêtre. Représente les zones qui ont brillé.

Canal 1 — Comptage négatif

Nombre d'événements p=0 par pixel. Représente les zones qui ont assombri.

Canal 2 — Timestamp moyen

Timestamp moyen normalisé dans [0, 1] pour les pixels actifs. 0 = pas d'événement.

Les 3 canaux d'un event slice de 25 ms. Le canal timestamp encode l'ordre temporel des événements au sein de la fenêtre.
# ms_model/representations/event_slice.py
def to_event_slice(ea, t_lo, t_hi) -> Tensor[3,H,W]:
    t_norm = (t - t_lo) / (t_hi - t_lo)       # normalise → [0,1]
    np.add.at(pos_count, (y[pos], x[pos]), 1.0)
    np.add.at(neg_count, (y[neg], x[neg]), 1.0)
    np.add.at(ts_sum,    (y,      x     ), t_norm)
    ts_agg = np.where(ts_cnt > 0, ts_sum / ts_cnt, 0.0)
    return torch.from_numpy(np.stack([pos_count, neg_count, ts_agg]))

7. Architecture ConvLSTM v1

Le modèle ConvLSTMSeg (ms_model/models/convlstm.py) est un réseau récurrent convolutif qui traite une séquence temporelle de voxel grids.

Déroulement temporel du ConvLSTM : à chaque timestep, l'encodeur extrait des features spatiales, la cellule LSTM maintient un état caché, et la tête prédit les logits de segmentation.

Cellule ConvLSTMCell

La cellule ConvLSTM fonctionne comme un LSTM classique, mais les opérations matricielles sont remplacées par des convolutions 2D :

# ms_model/models/convlstm.py — ConvLSTMCell
gates = Conv2d(in_dim + hidden_dim, 4*hidden_dim)(cat([x, h]))   # 4 gates
i, f, o, g = chunk(gates, 4)
i, f, o = sigmoid(i), sigmoid(f), sigmoid(o)   # input, forget, output gates
g = tanh(g)                                     # cell gate
c = f * c + i * g                               # cell state update
h = o * tanh(c)                                 # hidden state

8. ConvLSTM v2 — Encodeur enrichi

La version convlstm_v2 améliore v1 avec :

  • 2 convolutions par étage (vs 1) — plus de capacité d'extraction de features
  • GroupNorm après chaque conv — remplace BatchNorm, stable sur petits batchs
  • Tête à 2 couches 1×1 conv — permet une combinaison non-linéaire avant le logit
Aspectv1 (convlstm)v2 (convlstm_v2)
EncoderConv2d(stride=2) + ReLU2×(Conv2d + GroupNorm + ReLU)
NormalisationAucuneGroupNorm (num_groups=8)
TêteConv2d(1×1) → 1 canalConv2d(1×1) → ReLU → Conv2d(1×1)
hidden_dim par défaut3264

10. Pipeline EV-IMO — Vue d'ensemble

EV-IMO est un pipeline de Structure-from-Motion compositionnel qui prédit simultanément trois sorties à partir d'event slices :

Depth

(B, 1, H, W)
Profondeur de scène en mm (positive). Supervisé par le GT EVIMO.

Poses

(B, 6+3C)
Ego-motion 6-DoF + 3D translations par objet. Auto-supervisé via warp loss.

Masks

(B, C+1, H, W)
Poids de mélange softmax : fond + C objets. Semi-supervisé.

Vue d'ensemble du forward pass EV-IMO. Les flèches en pointillés indiquent une connexion indirecte (depth n'entre pas dans compute_flow).

12. Depth Network

La DepthNetwork (ms_model/models/evimo/depth_net.py) prend la slice centrale des 5 slices contexte et prédit une carte de profondeur dense.

# DepthNetwork.forward
depth_raw = ECNBackbone(in_channels=3, out_channels=1)(slice_centre)  # (B, 1, H, W)
depth = F.softplus(depth_raw)   # → valeurs positives (mm)
Softplus comme activation finale : softplus(x) = log(1 + exp(x)) — garantit une profondeur strictement positive, avec un gradient non nul même pour x < 0 (contrairement à ReLU).

14. Calcul du Flux Optique

Le flux n'est pas appris par un réseau — il est calculé de façon différentiable à partir des poses et masques prédits, via le modèle de projection caméra (Équation 1 du papier EV-IMO).

Pose par pixel — modèle compositionnel

Chaque pixel (u, v) a un mouvement qui est la somme pondérée de l'ego-motion et des mouvements d'objets :

p_pixel = p_ego + Σj mij · [tj ; 0 0 0]

m_ij = poids du mask softmax pour le pixel i et l'objet j
t_j = translation 3D de l'objet j (pas de rotation — simplification EV-IMO)
p_ego = [vx, vy, vz, ωx, ωy, ωz] commun à tous les pixels

Équation de projection (Éq. 1 EV-IMO)

Une fois le mouvement 6-DoF par pixel connu, le flux 2D est calculé via les coordonnées normalisées :

# Coordonnées normalisées (déprojection via intrinsèques K)
xn = (col - cx) / fx
yn = (row - cy) / fy

# Flux normalisé (Éq. 1 papier)
u_n = 0.5 * (-vx + xn*vz) + (xn*yn*wx - (1+xn²)*wy + yn*wz)
v_n = 0.5 * (-vy + yn*vz) + ((1+yn²)*wx - xn*yn*wy - xn*wz)

# Flux en pixels
flow = stack([fx * u_n,  fy * v_n])   # (B, 2, H, W)
Cette formule est la dérivée partielle de la projection perspectivale par rapport au temps, linéarisée autour du mouvement de la caméra. Elle transforme un mouvement 3D rigide en déplacement 2D dans l'image.

15. Losses EV-IMO

WarpLoss — auto-supervisé

Mesure la netteté des événements après déformation par le flux prédit. Si le flux est correct, les événements des slices voisines, ramenés au temps central, doivent ressembler aux événements du centre.

Les 4 slices voisines sont inversement déformées vers le temps central. Un flux correct les rend semblables à la slice centrale.

DepthLoss — supervisé sparse

# Pixels valides uniquement (GT depth != NaN)
ratio    = max(d_gt/d_pred, d_pred/d_gt)   # ratio symétrique ≥ 1
abs_rel  = |d_pred - d_gt| / d_gt          # erreur relative
L_main   = mean(ratio + abs_rel)           # = 1.0 si pred == gt
L_smooth = lambda * mean(|Laplacien(depth)|)  # régularisation 2e ordre

MaskLoss — semi-supervisé

Piège critique : Une MaskLoss qui ne supervise que les pixels de fond peut mener à une solution triviale "tout-fond" avec loss = 0. La correction est de superviser tous les pixels — en forçant bg_channel ≈ 1 au fond ET bg_channel ≈ 0 sur les objets. 
# Bonne formulation (v2) :
bg_proba  = masks[:, 0]                      # prob. fond
bg_target = (mask_gt == 0).float()          # 1 aux pixels fond, 0 aux objets
bce = F.binary_cross_entropy(bg_proba, bg_target)  # pénalise TOUT

# + régularisation spatiale
smooth = mean(|Δy masks|) + mean(|Δx masks|)
L_mask = lambda_bce * bce + lambda_smooth * smooth
